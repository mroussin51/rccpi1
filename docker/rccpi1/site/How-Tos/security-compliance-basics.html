Security & Compliance Basics on AWS

Set a practical security baseline

Turn on MFA, enforce least‑privilege IAM roles, and block public access to sensitive storage. Use HTTPS everywhere with managed certificates. Centralize logs and set alerting on unusual sign‑ins and permission changes to catch risk early without noise.

Steps

  1. Require MFA for root and admins.
  2. Use roles, not long‑lived keys; rotate secrets.
  3. Block public access to buckets; enable encryption.
  4. Enable CloudTrail, log to a separate account/bucket.

Key figures

  • Key rotation: 90 days (max) if any exist.
  • TLS: Only strong ciphers; HSTS enabled.

HIPAA basics for small practices

Use HIPAA‑eligible services and sign a BAA with the provider. Limit PHI to necessary systems, encrypt data in transit/at rest, and maintain access logs. Create an incident response plan and train staff on least privilege and secure handling of PHI.

Steps

  1. Sign BAA; restrict services to eligible ones.
  2. Encrypt data; restrict access via IAM and networks.
  3. Log access; retain per policy; review regularly.
  4. Document incident response steps and contacts.

Key figures

  • Access review: quarterly minimum.

Encrypt data at rest and in transit

Use managed KMS keys for storage and database encryption, and enforce HTTPS/TLS for all endpoints. Rotate keys per policy and restrict who can use or manage them. Validate certificates and cipher policies to keep compatibility while staying secure.

Steps

  1. Enable encryption on S3, EBS, RDS with KMS.
  2. Force HTTPS on ALB/CloudFront; redirect HTTP to HTTPS.
  3. Limit KMS key usage via IAM conditions.
  4. Rotate keys and audit grants periodically.
