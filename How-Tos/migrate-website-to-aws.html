Migrate WordPress with CloudFront and RDS

Freeze content, export database/files, provision RDS for MySQL, and move uploads to S3 with a plugin. Put CloudFront in front of the site and warm the cache. Dry‑run DNS cutover, then flip TTL‑reduced records during a low‑traffic window with a rollback ready.

Steps

  1. Freeze changes; back up DB and wp-content.
  2. Provision RDS; import DB; update wp-config.php.
  3. Move media to S3; integrate CloudFront.
  4. Warm cache; test with hosts file or preview domain.
  5. Reduce TTL; execute cutover; monitor and rollback if needed.

Key figures

  • Pre‑cutover TTL: 60–300s.
  • Cache warmup: homepage + top 20 URLs.

Lift‑and‑shift a LAMP stack with minimal downtime

Snapshot the server, rsync files to new instances, and use a temporary read replica or maintenance window to migrate the database. Verify app health behind a temporary hostname and swap DNS only after automated smoke tests pass.

Steps

  1. Snapshot source; rsync app and configs.
  2. Establish DB replica or maintenance window.
  3. Run smoke tests on the new environment.
  4. Switch DNS; monitor errors and logs.

Key figures

  • Downtime target: < 15 minutes for DB cutover.

DNS cutover checklist you can trust

Lower TTL, validate new endpoints, set health checks, and use weighted routing to shift a small portion of traffic first. Keep old infra warm for rollback. Document exact records to change, with timestamps and success criteria to avoid confusion.

Steps

  1. Lower TTL days ahead; confirm propagation.
  2. Validate new IPs/ALB/CloudFront and TLS.
  3. Use weighted routing (e.g., 10% → 50% → 100%).
  4. Keep old stack hot for fast rollback.

Key figures

  • Rollback commitment: < 30 minutes to revert.
