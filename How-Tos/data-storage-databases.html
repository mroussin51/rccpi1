S3 vs EFS vs EBS—what goes where

Use S3 for object storage and static assets, EFS for shared POSIX file systems across instances, and EBS for block storage attached to a single instance. Match durability and performance needs, and apply lifecycle rules to control long‑term costs.

Steps

  1. Classify data: object, shared FS, or block.
  2. Apply lifecycle and versioning to S3 where needed.
  3. Right‑size volumes and IOPS to match workload.
  4. Back up regularly; test restores.

Pick RDS, Aurora, or MySQL on EC2

Choose RDS for managed convenience, Aurora for higher scale and availability, and self‑managed MySQL on EC2 only when you need deep customization. Start managed, then reevaluate if constraints appear.

Steps

  1. List requirements: scale, HA, extensions, budget.
  2. Default to RDS MySQL/Postgres for simplicity.
  3. Move to Aurora if you need higher availability.
  4. Self‑manage only with strong DBA experience.

Migrate databases with near‑zero downtime

Use replication or a managed migration service to keep target in sync. Schedule a short write freeze, promote the target, and point apps at the new endpoint. Validate data row counts and error logs before declaring victory.

Steps

  1. Set up replication or migration service.
  2. Sync and monitor lag until cutover time.
  3. Freeze writes; promote target; update endpoints.
  4. Validate data, logs, and performance post‑cutover.
